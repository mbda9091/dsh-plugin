## 4. 具体方案
### 4.1 环境数量与目录

以下结构已在 M1 实现；M2 增加的元数据与入口见第 4.6–4.9 节：

```text
<repo>/node_modules/.../dsh          已有：开发、普通真实测试使用
<repo>/.local/environment-tests/
  owner.json                       已实现：仓库归属和格式版本
  host/                            已实现：唯一的外部测试宿主，跨次复用
  ready.json                       已实现：输入指纹、宿主身份、内容摘要及准备完成记录
  host.lock                        已实现：准备及使用期间的独占锁
<repo>/.tmp/environment-tests/run-*/
  report.json                      已有：本次实际测试结果
  <case>.json                      已有：每项证据
  shared-host.json                  已实现：本次准备/复用、安装次数、各项 home 与释放状态
  shared-host/                     已实现：本次宿主安装及版本检查日志
  repo .../                        已有：各用例独立 home/profile、临时源码
```

共享的是宿主程序文件；profile 的 node_modules 存放插件依赖，仍归各用例所有，不能共享。首次执行任一 TGT 用例才准备共享宿主。完整套件最多新增一个共享宿主和一个 TOOL-04 冷安装宿主，不包含 `--keep` 或旧失败现场。

不按版本无限新建缓存目录。输入失效后，在确认归属并获得独占锁的前提下重建同一个受管 host。未获得锁或归属不明时停止，不覆盖不明目录。宿主的程序复用与失败现场的诊断留存是两件事：后者即使暂时保留，也不能拿来当下次测试的有效环境。

### 4.2 宿主准备与复用

M1 将归属、指纹、安装、文件检查和使用锁放在 `scripts/src/core/environment-host.ts`；`test/src/common/harness/environment-host.ts` 管理惰性获取、用例串行及 `after` 收尾。TGT 的 `prepare()` 只获取宿主入口并创建自己的 profile，生产安装器不参与测试宿主选择。

准备输入包含：根声明 DSH 精确版本、根 lockfile 和 pnpm-workspace 配置哈希、所选 Node 实路径/版本/ABI、pnpm 脚本身份/版本、OS/架构，以及 helper 的准备格式版本。所选 pnpm 的公开 `config list --json` 在内存中读取实际生效的安装配置并摘要，包含已配置 hook 文件字节；认证、网络传输和 store 路径不参与内容失效，原始配置及凭据不写日志。插件源码变化不触发宿主重装。

流程：

1. 验证工具与目录归属；获取独占锁，整个选中 TGT 用例组使用期间持有。并发测试遇锁明确失败，不重复安装。M1 对遗留锁保守停止并提示核实；没有足够的子进程退出证据时不自动抢占，不能只按 PID 判定安全。
2. 对已完成记录检查输入指纹、宿主树内容/文件模式摘要（含清单和 lockfile）、DSH 包身份和入口真实路径，运行当前 Node 驱动的 `dsh --version`。摘要记录链接目标，不沿链接遍历；DSH 入口实际路径必须处于受管 host 内，不能回退到 workspace 或全局 DSH。
3. 合法则复用，报告 `reuse`。不合法则记录失效原因，清除本工具拥有的旧 host 后安装一次；沿用系统 registry、代理、证书及包缓存/store，不创建专用 store。
4. 保持当前独立宿主的 pnpm install 语义，保存宿主自己的 lockfile。它不等于复制 workspace 的整个依赖树，也不声称两者传递依赖逐字节相同。根锁变化仍主动使缓存失效。
5. 安装先在本次 run 的唯一 staging 完成，核对实际配置与共享目标相同；进程组停止后，校验链接内聚和无 staging 绝对路径，再独立复制文件到持锁且未发布的 host，并核对复制前后两棵树摘要。复制不使用硬链接或 installer 目录重命名，防止脱离原进程组的安装进程按旧目录延迟写入共享宿主。删除不用于运行的 pnpm 增量安装状态文件；该 host 不再运行增量安装。安装、复制及身份验证全部成功后才写 ready；失败不写可复用记录，日志归本次 run。
6. 保留 TGT-04 对宿主目录未变的断言；获取及组结束时校验宿主内容，变化时本次失败并使 ready 失效。作用域跟踪所有实际异步命令的进程组；即使上层捕获命令错误，退出未确认的组仍阻止成功清理 fixture 和释放共享锁。用例组等待实际异步工作及所拥有进程组收尾后才在 `after` 释放锁；`node:test` 超时不能提前解锁。锁释放成功后才把宿主证据标记通过。

上述进程组证明用于 macOS/Linux。Windows 缺少 Node 原生 Job Object 控制，不以 leader 退出或 PID 快照冒充完整树退出；保持原逐用例独立宿主与原测试断言，主报告明确 `isolated`，不申请共享锁、不声称共享验收通过。本轮真实验收仍为 macOS；Linux/Windows 未实机验收。

已有文件输出捕获、工具版本检查和安全路径函数可以复用；不使用管道捕获，不另造 pnpm 定位规则。准备时的安装副作用仅发生在受管 host 和系统包缓存，日常 DSH home/profile 不参与。

### 4.3 用例之间仍独立

- TGT-04 使用空的测试 profile 验证交付；宿主路径须与 workspace DSH 不同。
- TGT-05-real 使用自己的 profile 先装旧链接/旧 tarball，再覆盖；源码保持断言继续保留。
- TGT-06-real 使用自己的 profile 注入第二包失败；其 NODE_OPTIONS 只作用于该次调用，不进入共享宿主准备或后续用例。
- 三项的 home、profile、插件目录、日志和端口均不同。共享宿主没有共享会话，不常驻运行服务。
- TOOL-04 保留自身 checkout 和空 store，不读写上述 host；即使共享宿主已就绪，也必须实际执行本次冻结安装。

报告在现有 run 内增加宿主路径、指纹、`prepared/reused/failed`、本次宿主安装次数及引用用例。三个用例各有本次行为证据；共享安装准备不等于共享或复用旧的测试通过记录。

### 4.4 宿主生命周期与既有清理边界

共享宿主安装并验证成功后持续保留，不设置到期天数；环境、依赖和准备规则不变且校验通过，就可以一直复用。插件源码变化、用例成功或插件行为测试失败，本身都不导致宿主重装。

输入变化、宿主缺失或损坏、检测到宿主被修改时，使 ready 失效；下次需要使用前，在确认归属并获得独占锁后重建同一受管 host。半成品没有 ready，不能复用。无法确认归属或使用状态时停止，不擅自删除目录。

每个用例的 home/profile 仍归自己的 fixture。成功后的原有 fixture 清理不能删除共享 host，失败和 keep 也不把共享 host 复制进现场。host 位于 fixture 之外，引用关系和身份保存在本次报告里；保留现场不承诺永久固定宿主版本，后续环境变更时宿主仍可能重建。

M1 保留了成功清理、失败或 keep 留存的原行为。M2 在此基础上新增推送时的历史回收，不把已有六套旧 DSH 当作共享宿主的缓存来源；是否回收须另行验证归属、退出状态和保留条件。

锁释放和受管失效重建按第 4.2 节实现；fixture 和子进程仍按现有测试 harness 收尾。上述必要收尾失败时如实报告，不因共用宿主而跳过现有检查。

### 4.6 v0.6：原生 pre-push 自动尝试清理

根 postinstall 先执行 `node scripts/git-hooks.mjs setup`，编译脚本、校验当前根具有自己的 Git 元数据并核对 Git 根，然后注册本工具的 `hook.repo-test-cleanup`；之后继续原 `.security/setup.sh`。任一步失败仍使依赖安装失败。导出的无 Git 元数据副本在安全安装器执行前停止，不能配置父仓库。手动修复注册也使用上述 setup 命令，无需修改日常 push 命令。

注册只写当前仓库的具名原生 hook，不修改 core.hooksPath、不替换旧 hook 或安全扫描配置。注册命令使用安装时的普通 Node 绝对路径及相对脚本路径；Git 在发起工作树根运行，因此 linked worktree 只清理自己的临时数据。重复 setup 幂等，可更新本工具所用 Node 路径；禁用或冲突配置报错，不能覆盖其他来源。

用户照常运行 git push。pre-push 直接加载安装/开发命令已准备的编译输出，不运行 tsc、不写构建目录；失败/dry-run 也可能已执行清理，不能再承诺“只有成功推送才清理”。Git 在 hook 之前报错或用户明确使用 --no-verify 时不会触发。IDE 需调用支持该原生 hook 的 Git 且未禁用 hook。

测试持锁时立即跳过，不等待、不终止测试。清理失败、编译输出缺失或 Node 不可用只提示并让本 hook 返回成功；这不改变其他安全 hook 的失败退出，也不修改测试门禁。显式清理命令失败仍返回非零。测试自身成功收尾照常，测试前后不扫历史，不安装后台任务。

### 4.8 M2：一个共同锁，一份简单收尾记录（已实现，提交见第 9.12 节）

测试与历史清理使用一个仓库级共同锁，覆盖整个执行过程，不允许边测试边回收。CI 最外层持锁，内部 L1–L5 调用沿用外层锁，不重复争锁；独立 test/test-env/L4/L5/verify-artifacts 入口也通过同一个命令级边界。包或证据消费者如果会直接访问候选临时目录，也沿用这个边界，不建立逐资源租约。

清理时持锁扫描并删除；这允许另一条测试命令等待清理完成，是用本地串行换取简单。测试已持锁时清理立即跳过；清理已持锁时新测试等待，允许取消。锁占用或遗留不按 PID 自动抢占，人工核实后处理。开发及系统包缓存不进入回收范围。

每次新 run 只保存一份简单收尾记录：仓库归属、开始/结束时间、成功或失败、keep、正常收尾是否完成，以及固定格式的可删临时数据路径。开始时写 keep，结束后确认已等待自身任务和已知子进程再标正常完成；中断或退出未确认则保持未完成。记录是识别依据，不是把未知后台进程强行标为已退出。

可删路径由本工具的固定临时数据目录约定生成，只覆盖依赖树、测试 home、专用冷安装临时数据及安装 staging；路径必须位于当前 run 内并匹配固定目录约定，不能从记录中接受任意路径或通过 `..` 扩大范围。不把整个源码 fixture、报告目录或未知目录加入名单。执行前核对根/祖先不是被替换的链接；删除不跟随符号链接，不触碰系统 store 或 workspace DSH。

遇到显式 home 或特殊消费路径落在历史 run 内，保持原命令可用，但先将该 run 标为 keep 并给出提示；不推断引用图或在命令结束后自动解除。这样保护独立命令的新失败现场，不依赖旧 run 曾经成功或已经过期。解除 keep 和旧现场处理本期采用明确核实后的单独操作，不新增通用接管/恢复系统。

## 7. 风险与明确限制

- Git 未调用 pre-push、--no-verify 或 IDE 禁用 hook 时不会自动清理；长期不 push 可选主动 apply。Git dry-run 也可能清理。
- 清理持有共同锁时新测试会等待；本地串行是主动接受的取舍，不再承诺慢删除期间测试并行启动。
- 普通失败保留 7 天，keep 与证据继续保留；总占用无硬上限。后续若它们确实成为大头，再按测量单独讨论。
- 旧格式和异常退出目录可能继续占空间，不伪装成“自动回收了全部历史数据”；存量另行核实后处理。
- 历史临时数据不作为长期依赖。显式特殊路径通过 keep 保留，不能依赖自动引用推断；不减少正常独立测试能力。
- v0.5 本机 macOS 的原完整 CI 和回收后联验已通过；Linux/Windows、桌面及真实 DSH 沙箱未在本轮实机验证，不扩展为跨平台能力结论。
