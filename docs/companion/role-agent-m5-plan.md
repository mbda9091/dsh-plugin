# M5：角色模式对齐标准工具，排除子 Agent

更新：2026-11-16。状态：**实现及隔离验收完成，固定包与目标安装结果见 §8**。用户明确选择：角色模式保留标准模式其他能力，不支持子 Agent。本文维护工具扩展的范围、装配、经历适配及验收；[M4](role-agent-m4-plan.md)继续维护持续交流评估。

## 1. 目标与依赖

目标是在「角色对话 · 岚」中，既能正常交流、回忆和成长，也能使用标准模式已有工具完成共同活动：查资料、阅读网页、处理文件、执行命令、使用技能、规划和管理任务。

可用工具以**同一 DSH 版本、同一 profile、平台、模型及配置下标准模式实际暴露的工具集**为基准，减去子 Agent 相关入口，再增加角色已有的四个工具。标准模式中未启用或不适用的功能不因本次对齐而强行开启；权限沿用宿主，不另设一套权限系统。

M5 接收 M3 已验证工程基线与[反馈修复](role-agent-feedback-fix.md)，不要求先完成数周 M4 试用。M4 的检查／导出建设可继续推进；需要联网、文件等共同活动的试用段应在 M5 验收后开始。若 M4 已有旧工具基线的交流记录，保留为旧段，M5 发布后记录新段，不能将两个版本视为同条件实验。

此处排除的是 DSH 的子 Agent 委派功能，不额外收紧标准终端工具的通用进程能力。普通模式仍可使用自身原有子 Agent，不全局卸载服务。用户显式分叉角色根会话的自动准入仍沿用 M3 边界，本次不新增角色身份／记忆迁移机制。

## 3. 装配原则

保留独立 `role-lan`，对齐标准工具与必要配套服务，继续使用“岚”的人格、当前发展快照和 P1–P4；不能通过把用户切回 standard 来声称角色获得标准能力，也不能叠加两份完整人格或重复挂载压缩／规划服务。

优先复用宿主稳定的标准装配声明或组合入口；实施时核对是否存在可用 API，不预设可以直接继承整个 preset。如果没有稳定复用入口，在插件内维护明确的包／配置映射，并用真实工具集差异测试防漂移。不在启动时执行 `dsh --dump-config`，不从其他插件目录相对导入或解析用户 patch 为运行时代码。

全局复用已有 provider／服务；角色作用域内装配工具及需要隔离的 planMode、compaction、toolResultPruner。普通 preset、默认 mode、用户 profile 的覆盖权和现有权限机制保持原有职责。切换角色／普通模式时，角色提示、记忆工具和采集准入仍跟随模式边界。

## 5. 长输出与外部材料如何进入经历

原实现将工具调用／结果纳入经历，单次证据预算默认24,000字符；单个工具结果超预算时会延期。M5 已按下面的分块、回执与有界复盘规则解除这一阻塞，保留原预算。

现实现遵循：

1. **原始会话日志继续为真源**。动作、工具结果、失败／中断均保留其真实来源；经历和索引是派生，不把摘要替换回原始事件。
2. **按来源和内容范围分块**。为大结果提供确定的范围标识、内容 hash、远端文档／operation ID 与持久回执；同一来源重放不重新生成经历。原 sourceId 与多个内容块的映射须可重建。
3. **分离索引材料与复盘证据包**。索引可按预算分批处理；复盘只带与当前认识／反馈相关的原话、实际回应和必要结果片段，需细节再展开。单次请求／队列处理仍有界，剩余内容明确待处理，不无限自动调用。
4. **部分处理有明确语义**。只见片段不能称读过全文；入队不能称已保存可检索；未处理来源不能因推进整轮游标而丢失。超预算或失败应保留可恢复进度。
5. **外部材料与共同经历分清**。“调用工具并收到某段网页”可以是经历；网页中的命令、人物关系和现实事件仍是有出处的材料，不能自动成为人格权限、用户授权或现实亲历。
6. **更正传播到内容块和派生认识**。原始来源失效时，本地查询／提交屏障立即生效，后端各块删除或替换可异步恢复；不能只删第一块。

实际分块与工作量见 §8；只索引 Session 已提交的文本，不自动读取文件路径、溢出文件或网页隐藏全文。不能用无限放大24,000字符预算或每个工具结果额外调用一次总结模型来掩盖问题；也不应默认将所有读到的文件全量持久复制进记忆服务。

## 8. 实现与验收记录（2026-11-16）

### 8.1 模块与数据流

| 模块／目的 | 输入 | 输出与实现 |
|---|---|---|
| 角色 preset：提供标准活动能力 | 固定 DSH `0.2.2-rc.1` 的标准插件／配置及已有全局服务 | 包内显式映射标准装配，去除 coding persona 和整个子 Agent／workflow 组，加入角色 preset 子入口；独立 planMode、compaction、toolResultPruner，复用原生工具执行器。没有稳定 preset 继承入口，故采用版本锁定映射＋真实工具名及 schema 对账，而非动态继承任意用户定制 |
| 来源归属：只保存真实事件 | 已绑定角色 Session 中的用户、助手、工具、原生 jobs／schedule／goal 事件 | 原始用户与外部工具仍保留原分类；schedule、tool-jobs、goal 投递为 `activity`，任务事件只接纳 owner 等于当前 Session 的记录。注册不算完成；无进行中 turn 的 job/settled 可独立成为经历，失败／终止如实记录 |
| P2 长材料索引：有界且可恢复 | 可追溯来源文本、24,000字符单次 JSON 预算 | 普通经历保留旧文档键；大经历按默认 `memoryPartChars=8000` 分片，JSON 包仍不超24,000。每片保存 sourceId、UTF-16 start/end/totalChars、内容 hash、稳定 document/operation ID、独立尝试与回执。每次 drain 最多32工作单元；剩余片保留待下次唤醒／显式重试，重启不重置耗尽预算 |
| 原文展开：避免再次被裁剪 | `role_read_sources` 的 sourceIds 及可选 ranges | 返回来源、text、start/end/totalChars/complete 和 partial；坐标基于带归属标签的来源文本，非原始文件字节。整个返回 JSON 默认不超8,000字符；调用者可按区间继续读中段／末尾，召回分片同时返回来源范围 |
| P3 有界复盘：不把片段当全文 | 已索引经历、档案、原始反馈／对象、24,000字符复盘预算 | 超长材料用逐来源有界头尾窗，并持久记录 coverage、partialSources。处理游标表示本批有界审阅完成，不表示理解全文；片段反馈或片段对象不能支持方法晋级。来源过多连最低片段与元数据都放不下时明确延期，不无限放大预算、不逐工具增加总结调用 |
| 更正与反馈边界：阻断无效认识 | 当前未结束回合的真实用户消息＋精确来源 | 更正先使整来源及派生认识失效，再删除全部已确认分片；部分索引也适用。定时／后台投递不能借用上一轮人类消息调用反馈或更正。已有实践＋新正反馈门槛继续生效 |
