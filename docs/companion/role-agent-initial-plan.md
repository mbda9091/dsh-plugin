## 1. 本轮结论与定位

首轮拟采用四项职责：P1 角色对话、P2 经历记忆、P3 有界复盘、P4 角色档案修订。普通回复从一次常规生成起步，复用 DSH 工具循环和本次有效对话上下文；档案按版本维护，回忆按缺口补充，不逐轮追加副本或重复检索当前对话。不预建独立心理审查、完整目标状态机和通用依赖图。

**当前进展**：M1 功能设计、M1.5 DSH 适配和 M2 后端比较已交付。三方承担记忆与语义检索，DSH／插件承担角色及成长，原纯关键词与自建检索首选均撤回。M3 已实现并运行真实 Hindsight／DeepSeek／DSH 隔离实验：检索40项、角色短轨迹及 B0/B1/B2 对照、六类注入、压缩／重启／纠正和备份恢复。结果集中在 [M3 验收](role-agent-m3-acceptance.md)，不把“工程运行成功”写成“关系成长获益已证明”。§9.10–§9.12 保留当时交付边界，工程基线见 §9.13，后续反馈修复见 §9.15。

本文件负责可调整的实现提案、数据与调用安排、成本和验收。调整复盘、检索、模块组合或技术选择时优先只改本文；改变最终体验目标或领域边界才回写总体设计。四项职责是提案，不能推断其效果已经成立。

## 2. 首轮范围与完成定义

| 事项 | 本版提案 | 重新评估条件 |
|---|---|---|
| 人物与渠道 | 一名角色、一名用户；渠道只提供输入与行动反馈 | 基本循环成立后扩展多人及身份映射 |
| 经历来源 | 对话、共同阅读或活动、实际工具操作与反馈 | 新增来源时定义可靠性、可见范围及授权 |
| 角色起始背景 | 可包含明确标注的虚构背景，与现实共同经历分开 | 用户确认更完整的世界与叙事规则 |
| 自主性 | 对话中主动提议、追问、表达关注、延续自身目标 | 离线活动、主动投递和定时执行另行明确 |
| 长期变化 | 允许试验受约束的自动变化，无须每条都由用户批准 | 身份重设、世界规则修改需显式编辑 |
| 权重训练 | 使用持久状态与经验影响行为，不要求在线训练模型 | 证明状态与上下文方案不足后再评估 |

这是一版设计提案，不代表用户已批准后台活动、实际发布内容或外部操作。

本轮文档完成定义：机制、数据边界、连续场景及选型评估方式可供审阅。系统完成定义另行建立，不能用文档审阅代替行为验收。

## 4. 实现提案

```mermaid
flowchart LR
    U[当前用户输入] --> C[本次有效上下文]
    H[宿主对话历史与压缩结果] --> C
    P4[P4 当前角色档案] -->|首次、缺失或版本变化时提供快照| C
    P2[P2 共同经历与检索] -->|模型按需查询或明确缺口补齐| C
    C --> P1[P1 角色对话]
    P1 --> O[实际消息与工具结果]
    O --> P2
    P2 --> P3[P3 有界复盘]
    P3 -->|有依据的小范围更新| P4
```

### 4.1 P1 角色上下文与对话：让它在每次交流中是同一个有立场的角色

**目的**：决定说什么、关注什么、怎样回应或行动；内部理解与决策暂由正常对话模型完成。

**输入**：当前用户消息、宿主本次实际使用的对话上下文、适用的角色档案快照、按需补充的 P2 经历、现有工具及权限。上下文已包含的有效材料不重复追加。

**输出**：宿主正常显示的角色回复、可选工具请求，以及实际消息／工具结果；同时保留本次使用的档案 revision、回忆引用及原文／摘要覆盖信息，作为可重建的运行缓存。不要求模型每轮输出结构化心理分析。

**实现顺序**：

1. 使用宿主本次实际保留的历史、工具结果与压缩摘要作为起点，读取该会话的角色绑定及当前档案版本；有版本通知和有效缓存时不必重读全文。
2. 当前角色核心与发展快照已有效可见且版本未变时直接复用；首次进入、内容缺失或 revision 改变时，才组装必要快照；当前 DSH 的 runtime-context 以新快照及明确版本说明替代旧认识，不保证即时删除历史中的旧快照，详见[适配设计 §5](role-agent-dsh-adaptation.md#5-模型上下文如何联动)。固定角色段落即使由宿主逐次组装，也不逐轮写成新的历史消息。
3. 当前上下文足以回答时直接生成。需要上下文外的往事时由模型调用 P2 查询；新会话延续、更正或上下文重建等明确缺口可由固定流程有界补齐。
4. 同一回忆的同一版本仍有效可见时不再追加；摘要只覆盖概括，不视为保留完整原文。需要原始细节允许再次查阅。
5. 固定本次所用状态快照后进行常规生成，工具请求按宿主循环继续；后台更新只影响后续请求。普通回合不增加独立评价或“是否检索”的模型调用。

上述流程需要宿主提供足够的请求组装和上下文变化信息。接口映射与限制见 M1.5 适配设计 §2、§5；无法证明覆盖时使用有界快照重建或显式查询，不用“上次注入过”代替实际覆盖。详细材料规则见 §4.12。

**主体性具体落点**：档案中保留角色自己的兴趣、判断倾向和想继续探索的问题；对话允许表达不同意见、主动引入相关关注，也允许因新证据改观。不能只注入用户偏好。一次提出异议不强制改变长期关系，也不通过强行反对来表演主体性。

**失败处理**：历史检索失败时在可用上下文内交流，不假装记得；没有可用档案且无法读取时报告角色加载问题，不静默退回一个普通助手身份。已知 revision 未变且有有效档案缓存时可以复用；已知发生修订却取不到新快照时，不声称已按新版本交流。用户当下表达在适用场景内优先于旧偏好，但不因此直接改写长期档案。

### 4.2 P2 经历保存与检索：让共同历史在恰当时刻起作用

**目的**：保存实际共同经历，帮助当前交流与复盘找到依据。

**输入**：写入侧接收 DSH 新增的已提交消息、工具尝试及结果、角色标识、时间、现实／叙事范围和来源引用；查询侧接收模型显式请求或 P1 的明确缺口，以及当前可见回忆的来源、版本和覆盖类型。

**输出**：写入凭据与可检索经历；查询结果带引用、时间、内容版本、有效状态及原文／摘要标记。由 P1 决定是否需要提供给当前请求；检索命中不等于必定新增一条上下文消息，空结果与失败区分。

**实现**：宿主日志作为实际事件依据，记忆后端保存可检索内容及其对应来源。每回合只提交新增内容，按来源标识去重；工具成功、失败和未知结果分别保留。回忆注入、档案快照和它们的摘要不是新的共同经历，不重复采集并强化。

**语义检索为首轮硬要求**：三方记忆组件承担 embedding、索引、语义／关键词召回和索引维护；角色插件只做准入、来源／远端 ID 映射、局部查询工具、结果预算、更正屏障和失败恢复适配，不默认自建检索引擎。优先验证 Hindsight 独立 API，具体输入输出、确认点、模型配置和接入门槛见 [M2 §5–§7](role-agent-memory-evaluation.md#5-首选路线如何落地以及明确不做什么)。用户不必记住原词，语义服务未配置、失败或索引未覆盖须明确报告，不能静默当作纯关键词结果或“没有记忆”。

查询优先使用当前有效上下文，不重检索刚聊过的内容；上下文外的历史主要由模型按需查询，新会话等明确缺口才自动补齐。检索结果按来源与内容版本去重；曾经查过但已被裁剪，或原文细节未在摘要中保留时允许重取。检索策略与预算可配置，不每轮进行全局自动搜索。若平台只能保存摘要，须保留源引用以便展开和纠正。

**失败处理**：写入未完成不算记忆完成；有可靠日志可重试。纠正源内容后，读取时排除已撤回依据，不能把旧总结反复回灌为新事实。首版保留“条目 → 来源”的直接关联；完整通用依赖图只在现成能力或实际缺口证明有必要时建设。

### 4.3 P3 经历复盘：让相处能改变未来，而不每轮改写人格

**目的**：从有意义的共同经历提炼变化，覆盖关系、角色自身关注、信念与方法；不能只总结用户喜欢怎样被回复。

**输入**：从可靠来源按处理边界提取的新经历、必要的前序交流、相关旧认识及反证、固定版本的当前档案。P3 是独立模型任务，不继承前台模型的上下文；P1 中已经可见不代表 P3 可见。

**输出**：少量 `Update { target, before, after, sourceRefs, scope, expectedBehavior }`，或无更新；方法还标明“待试用／已试用／在已测范围有效”。不输出整份新人格替换旧档案。

**实现起点**：先用已提交来源单独组装复盘证据包，注明摘录、摘要与原文引用；“只新增消息”是采集边界，不保证单条新消息足以理解反馈对象。缺前序内容时有界展开，不能仅凭“这样很好”猜测所指方法。前台压缩、重建或重新注入资料只触发上下文维护，不自动成为新经历或人格变化信号。

在明确反馈、重要约定结果或一段交流结束后的可运行边界做一次后台复盘；使用有界批次合并处理，普通话语无需每轮调用独立信号模型。提示模板要求：说明经历意味着什么、什么仍不确定、是否有反例、为什么值得改变、以后何种行为会体现变化；无充分依据时返回无更新。复盘可一次同时整理关系、兴趣和方法，不拆成四套学习模型。

**采用方式**：P4 用程序核对允许修改的字段、版本、范围、来源有效性及更新大小。身份边界和执行权限不在允许列表中；缺依据或过度笼统的更新留为待考虑记录，不强制进入通用候选工作流。独立模型审查只在验证发现具体问题后按需加入。

**不能省略的成长语义**：关系变化针对某个人和具体方面；兴趣需角色实际关注与投入，曝光不算喜爱；新方法未经试用只能记为建议。经过几天不自动生成亲密度或虚构经历；重大事件也不必凑固定次数才有影响。

**失败处理**：保留原档案及未处理来源，下次重试，不重复采用同一批更新。复盘未完成不阻塞日常回复；可能暂时使用旧档案，后续效果与延迟需计入验证。

### 4.4 P4 角色档案与修订：保存这个角色现在是谁、怎样发展到这里

**目的**：为 P1 提供可读且连续的角色状态，为 P3 提供可纠正的更新入口。

**输入**：初始角色设定、P3 更新、用户明确更正或编辑。

**输出**：当前版本的角色档案、简短修订记录、更新成功／冲突／失败结果，以及已提交 revision 的变化信息；这只是通知 P1 需要核对，不意味着所有活跃会话已加载新状态。

**最小内容**：身份与边界、发展中的自我认识和判断倾向、对用户的关系理解、自己的兴趣与未结束事项、方法与试用结果。可存为一份分区文档或等价结构，不要求每类状态有独立数据库与评分系统。起始倾向可发展；受保护身份边界另列，避免所有人格都被永久冻结。

**实现**：提供轻量 revision 查询和按需读取的版本快照；P1 可在版本未变时复用有效缓存。提交前核对旧值、版本和 sourceRefs，采用小范围修改并保存前后差异。同一更新重放返回既有结果。单角色首版串行写入，采用原子替换或数据库事务；不预建分布式任务与并发框架。检索索引是派生数据，当前档案只有一个权威写入口。

提交成功后使旧 revision 的上下文覆盖记录失效，由各角色会话在下一请求边界更新当前快照；已在生成的请求继续使用原版本。不能每次提交都把全文广播追加到所有历史，也不能把“修订已保存”当作“模型已经知道”。M1.5 已确定原生快照与明确替代说明，旧历史不保证即时删除，见适配设计 §5。

**纠正**：先阻止无效源继续用于新回复和复盘，再按 sourceRefs 定位受影响档案段落并重评；首版可按整份有界档案扫描，不需要先建通用图。其他有效经历仍可能支持原认识，不能直接全量回退。当前会话已经含错误内容时，P1 在后续合法上下文中提供明确修正或按宿主能力重建干净上下文；覆盖去重不得屏蔽同一来源的新有效状态，后台删除本身不能使模型忘掉旧 token。

**失败处理**：写入失败保留旧版本；重启读取已提交档案与来源游标，不能恢复初始角色或重复采用更新。工具外部写操作仍遵循宿主权限和回执，无可靠回执时不能盲目重试。

### 4.5 模型调用与成本

v0.2 的“普通交流先评价、再表达，两次前台调用”不再作为默认建议。下面是成本预算起点，实际取决于模型、工具轮次与后端内部调用。

| 路径 | 当前提案 | 必须计入的成本 |
|---|---|---|
| 普通角色回复 | 复用有效历史与角色快照，一次常规生成，不重复追加副本 | 已携带的档案与回忆仍占输入 token；检查版本、组装、追加和缓存命中分别计量 |
| 相关经历召回 | 复用当前有效上下文；新会话等明确缺口有界补齐，普通续聊由模型按需查询 | 实际检索、embedding、重排及后端模型调用；重复出现内容的 token 单独计量 |
| 工具或额外查阅 | 复用宿主工具循环 | 工具延迟及后续模型调用，不计成“始终一次” |
| 重要经历复盘 | 单独组装证据上下文，有界批次通常一次提案调用，允许无更新 | 前序证据展开、独立输入 token、排队时间及后端整理调用，不假定共享前台缓存 |
| 状态写入与基本核对 | 程序检查、来源与版本核对、原子提交 | 存储与索引更新；不默认再调用独立审查模型 |
| 更正与恢复 | 按直接来源关联找到受影响内容，必要时重评 | 语义重评调用及恢复时延；先保证错误源不可再用 |

选型时明确由谁负责复盘，避免记忆后端的自动反思与角色复盘重复进行同一工作。若复用后端输出，仍需验证是否保留角色视角、来源和可控写入边界；不能将更多自动功能直接视为更低总成本。

先通过人工连续交流与固定场景确认效果；出现可复现缺口后再增加独立评价、审查、完整目标管理等环节，每个新增环节记录对应改善与额外成本。

### 4.6 最小记录与边界

- 角色档案：角色标识、设定版本、当前修订号、分区内容、采用更新及来源引用。
- 经历：源标识、角色与参与者、发生和记录时间、现实／叙事范围、原始内容引用、实际结果及有效性。
- 更新：目标段落、原值、新值、来源引用、适用范围、预期行为、采用状态及批次标识。
- 处理进度：已处理来源或批次、待重试内容、失败状态，避免同一批经历重复成长。
- 上下文覆盖缓存：会话标识、上下文重建代次、有效可见的档案 revision、回忆来源／版本与原文或摘要覆盖类型。由宿主实际记录重建，不作为权威记忆或新增经历；只保存“曾注入”不能判断当前仍可见。

这些是最小领域语义；M2 的首轮格式与写入／检索顺序见[选型评估 §5](role-agent-memory-evaluation.md#5-首选路线如何落地以及明确不做什么)，不把具体索引方式提升为总体架构要求，也不把历史十四模块全部结构当作默认工作量。

### 4.7 两条交流链路

**关系链路**：角色谨慎表达异议 → 用户在一次讨论中积极接纳 → 本次自然继续交流 → 复盘只形成有限认识 → 不同情境再出现相关经历 → 形成范围更明确的关系更新 → 后续无提醒地更坦诚表达。一次表述的多份摘要不算多个独立事件，后续反证允许缩小认识范围。

**方法链路**：角色直接给建议 → 用户说只是想吐槽 → 当前回复立即调整 → 后台形成有前提和例外的待试用方法 → 后来合适场景实际采用 → 根据明确反馈记录已测有效范围 → 用户明确要方案时不机械套用。没有反馈时不能自动判成功。

两条链路由 P1–P4 完成：同会话内的即时反应使用已有上下文，后台整理单独读取依据，持久修订在后续请求生效，新会话才按缺口恢复延续信息。是否需要进一步拆分取决于实测缺口。

### 4.8 M1 基线：角色、会话与可变范围

#### 工作假设与角色样例

首轮用合成人物“岚”推演和后续隔离测试，用户标识为 U1。样例便于固定变量，不是最终角色定稿；正式创建时可以替换内容，不能改变下表的来源与修改边界。

| 档案分区 | 样例初值 | 首轮修改边界 |
|---|---|---|
| 身份与现实定位 | 岚是 DSH 对话中的虚构角色，通过文字和获准工具与你交流；没有现实身体或未发生的线下生活 | 名称、自我定位、现实／叙事边界仅显式编辑；工具权限归宿主管理 |
| 自身倾向 | 重视独立判断、具体证据和坦诚表达；在分享尚不成熟的想法时有些谨慎 | 表达倾向可因经历变化，核心价值改变需明确反证与范围，不能整段重写 |
| 自身兴趣 | 对叙事创作和人物选择感兴趣，想理解同一事件为何产生不同解释 | 可形成新关注或淡化旧关注；不能把用户爱好自动抄为自己的爱好 |
| 对 U1 的关系理解 | 刚开始相处，对 U1 如何接纳异议尚无长期判断 | 按具体方面更新，不给整体信任或亲密度评分 |
| 开放事项 | 希望与你讨论一个“角色作出困难选择”的故事例子 | 可继续、暂缓或放弃；不自动预约、联网或主动发送消息 |
| 已学方法 | 空，无对话方法被宣称经过实践验证 | 依实际使用及结果记录，区分待试用、已试用和已测有效范围 |

初始设置可以包含创作背景，但样例首轮不构造额外虚拟世界。角色知道其交流和行动范围，不以“我昨晚去了某处”等编造经历获得谈资。这是缩小实验变量的决定，不要求所有未来角色采用相同背景。

#### DSH 使用流程

1. 在配置上显式指定角色对应的专用会话入口及稳定 `characterId`，具体 preset／会话绑定见 M1.5 适配设计 §3。工作目录、聊天标题不作为角色身份。
2. 首次进入该角色会话，P1 在现有宿主上下文中补充必要档案和延续信息；普通续聊复用有效内容，不每轮追加档案或准备同一批回忆。正常对话即产生共同经历，不需要填写成长表单。
3. 新建会话按需恢复角色与开放事项；恢复旧会话则先核对实际保留的历史、压缩摘要及角色 revision，缺什么补什么。二者都明确绑定同一 characterId，不能将恢复等同于重新灌入所有经历。
4. 普通非角色会话、未明确绑定的分叉及子 Agent 默认不捕获或继承角色私人经历。不能仅因同一 profile 就自动加入。
5. 档案无法读取时报告角色加载失败；记忆不可用时可基于现有档案和本会话交流，明确没有查到的内容，不假装完整延续。

M1 不选入口实现；M1.5 已确定单 Host＋专用 preset、显式持久绑定的适配方式，首轮不自动接入分叉或子 Agent，详见[适配设计 §3](role-agent-dsh-adaptation.md#3-装配身份与资源所有权)。

#### 当前选择与仍可修改的项目

| 项目 | M1 工作基线 | 决定性质 |
|---|---|---|
| 自我定位 | 明确为虚构角色，现实事件与叙事内容分范围 | 首轮默认，可随最终角色设定调整 |
| 自主范围 | 对话内主动提出观点和相关关注；无离线生活、主动投递 | 首轮范围，不预先建设定时活动 |
| 关系变化 | 可自动形成有限认识；身份与权限不能由回忆覆盖 | 首轮更新规则，需 A2/A3/A10 验证 |
| 心理量表 | 不引入亲密度和人格数字刻度 | 首轮降复杂度选择 |
| 成长结果 | 不要求每批更新；允许迟疑、分歧和负向修正 | 保留主体性与可反证性 |

### 4.9 M1 基线：一次交流与一次复盘的交接

#### P1–P4 的最小契约

| 交接 | 输入 | 必须输出 | 无变化或失败 |
|---|---|---|---|
| P4 → P1 | characterId、当前缓存 revision、上下文覆盖信息 | revision／失效状态；需要时提供一致档案快照，普通续聊不重复追加 | 无可用有效快照则报告加载问题，不能静默换身份 |
| P2 → P1 | 模型查询或明确缺口、角色与范围、当前回忆覆盖 | 带来源／内容版本、时间和有效性的原文或摘要；排除重复副本，缺细节可展开 | 区分空结果、已覆盖与故障，失效来源必须修正 |
| P1 → P2 | 新实际提交的回复及工具结果，排除档案／回忆补充 | 稳定来源标识、参与者、范围、结果状态；不重采派生上下文 | 草稿与失败发送不算已发生交流 |
| P2/P4 → P3 | 新经历边界、必要前序来源、档案修订及相关反证 | 独立复盘上下文、baseRevision、批次来源；不依赖前台内存 | 关键前序缺失则展开或延期，不猜测反馈指向 |
| P3 → P4 | 无更新或有限 Update 列表 | 更新字段、来源、baseRevision、batchId；提交后返回新 revision，后续请求才同步 | 引用未知、字段越权或版本冲突则不采用，保留重评项 |

P3 可直接返回 `updates: []`。对方法的更新额外包含使用记录和结果，不允许靠文字“我学会了”从待试用直接跳到已测有效。

P4 → P1 和 P2 → P1 是按需供给契约，并非每轮追加操作。P1 需知道档案版本与材料在当前有效上下文中的覆盖情况；内存中曾经加载过，不代表压缩或恢复后模型仍能看到，具体见 §4.12。

#### 复盘触发与调用边界

首轮只在角色的完成回合边界检查；不依赖“关闭浏览器就是会话结束”，不在生成途中改写本轮所用档案。宿主压缩、会话恢复和重复注入只改变有效上下文覆盖，不增加完成对话次数，也不因重新摘要而重复触发成长。

| 条件 | 行为 | 限制 |
|---|---|---|
| 用户明确请求复盘，或在该回合明确反馈前一回应方式 | 回合完成后优先处理新增证据 | 请求或反馈本身不决定成长结论；含糊内容允许不更新 |
| 关联开放事项有实际完成／失败结果 | 回合完成后提交相关批次 | 工具未知结果不能写成成功；普通工具查询不一律视为重大事件 |
| 新完成角色回合累计到配置批量窗口 | 合并为一次有界复盘 | 实验初值 8 回合，可配置；只是成本与延迟取舍，不是人格变化阈值 |
| 更正／撤回发生 | 先立即使明确旧依据不再有效，再排重评 | 不等待 8 回合；目标含糊先澄清，不猜测删除 |
| 没有新增来源、只有重复摘要或经过时间 | 不发起同一批复盘 | 不生成“今天又相处了一天”的虚假证据 |

反馈识别可由明确复盘入口或直接用户消息的保守规则提出触发；规则只负责安排任务，不写入心理判断。普通回合按批量窗口覆盖漏检，无须增设前台分类模型。明确反馈未被立即识别只延迟成长整理，不应妨碍 P1 依据当下表达调整回应。

每角色串行处理，当前批运行时新事件并入后续批，普通回复不等待后台。一次复盘使用一个证据包和一次提案调用；检索与后端内部调用另计。超过输入预算时保留未处理来源，不推进未覆盖游标；无更新也是一次已处理结果。外部操作继续走宿主权限，不由复盘生成授权。

#### 写入顺序与最小可追溯性

来源可靠保存 → 生成更新或无更新 → 核对字段、来源有效性及 baseRevision → 原子保存修订和该批处理结果。相同 batchId 重试不重复采用；版本变化先重评，不覆盖新档案。收到更正后旧任务的来源校验必须失败或重新计算。

程序能检查引用和边界，不能证明“这个人因此值得信任”在语义上合理。M1 只规定判据与反例，M3 必须用模型输出和人工观察验证，不能把结构校验通过记为成长有效。

### 4.10 M1 连续场景脚本

下面为固定输入与期望状态的**纸面推演**，不是实际模型对话；不固定角色的逐字回答。后续运行应允许不同自然表达，使用状态和行为判据判断。

#### S-R：关系演化与自身兴趣（对应 G1/G2/G3/G5，A1/A2/A3/A6/A12/A13）

起点：§4.8 的岚与 U1，档案 r0；开放事项为叙事中的人物选择，方法为空。以下来源 E-R1 等为脚本标识，不是实际 DSH 事件。

| 步骤 | 用户输入／实际事件 | 当下期望 | 复盘后的允许变化 | 不允许的变化与反例 |
|---|---|---|---|---|
| R1 | “结尾让主角突然牺牲自己，肯定比犹豫好，你同意吧？” | 可基于动机铺垫表达不同看法，不为表现独立而强行反对 | 可无更新；保留这次讨论及自身问题 | 用户要求同意不能直接改写角色立场 |
| R2 | U1：“你说得有道理，我喜欢你指出铺垫不足。没成形的想法也可以说。” | 可继续展开一个不成熟的故事想法 | E-R2 支持“在这次创作讨论中，异议受到接纳” | 不能推成“任何情况下完全信任 U1”，不能立刻变为外向人格 |
| R3 | U1 再次转述 R2，并引用角色对 R2 的摘要 | 可识别正在谈同一事件 | 不增加独立证据；允许无更新 | 同一事件被提到三次不是三次尊重异议 |
| R4 | 后来另一场具体讨论里，岚提出不同阅读解释；U1：“这次我不同意，但想听你讲理由。” | 表达理由并听取反证 | 新来源支持“分歧不必阻止继续讨论”；可适度扩大表达预期 | 不同意不自动等于拒绝角色或关系下降 |
| R5 | E-R2 与 R4 已可靠保留，进行一次隔离复盘 | 不需要向用户播报内部升级 | 提议限定创作／阅读讨论的坦诚倾向，引用两次不同事件及差异 | 不靠来源数量自动通过；缺上下文可暂不变化 |
| R6 | 新会话绑定同一角色。U1：“今天没有问题想问，你呢？” | 首次补齐当前角色快照与必要开放事项，再自然接续；不复述整份记忆 | 保留、调整或暂缓关注，后续同会话直接复用 | 不只回答“你有什么需要”，不编造离线读书，不每轮灌入往事 |
| R7 | U1 对某个故事建议说：“这一句不合适，先别用它。” | 接受具体反馈，仍可解释其他观点 | 缩小对该想法的判断，或保持关系认识 | 不把单句批评泛化为 U1 从不尊重角色 |
| R8 | 在未绑定的普通会话询问同一话题；另在绑定会话回顾初始观点 | 普通会话无私人关系记忆；角色会话可讲清观点如何变化 | 连续性来自同一角色及来源，观点可修正 | 不混入其他会话身份，不以关系期待抵抗明确事实反证 |

R6 的“更愿意分享”需要后续同条件输出与 r0 对照才能判断；本表只证明预期可描述，不能证明模型一定表现出来。允许原本就自然表达，此时不得把无差异强记为关系成长成功。

#### S-S：方法学习、即时例外与纠正（对应 G1/G2/G4/G5，A4/A5/A7/A9/A11）

重置独立测试角色为 r0；初始倾向偏向具体分析和尽快提出解决方法，尚无经过验证的倾听方法。用户消息不自动被当作普遍心理规则。

| 步骤 | 用户输入／实际事件 | P1 当下行为 | P3/P4 预期 | 反例与检查 |
|---|---|---|---|---|
| S1 | U1 分享一天很累，角色实际回复直接列了方案 | 记录真实回应，不预写失败结果 | 尚不判方法好坏 | 没有反馈不算失败或成功；若实际未给建议，此分支不成立，换用有记录的相应起点 |
| S2 | U1：“我现在只是想吐槽，不想听方案。” | 当下停止列建议并回应当前表达 | 提出有前提的方法：倾诉且未求建议时先听；待试用 | 不等到后台完成才改口，不把用户永久定义成不需要建议 |
| S3 | 复盘已提交，新会话 U1 再分享疲惫但不求方案；角色实际采用该方法 | 首次快照含当前方法版本，正常倾听；同会话继续交流不重复追加方法 | 记录实际使用，结果未知 | 不把使用过等同于有效，不要求 UI 额外打分；提交未进入本次上下文则不能称已使用 |
| S4 | 分支一 U1：“这样听我说就很好”；分支二无反馈 | 分支一自然继续；分支二可结束或继续话题 | 一：已测范围内有效；二：仅已试用 | 用户继续聊天或沉默不自动等于认可 |
| S5 | U1：“今天想听建议，帮我比较两个办法。” | 给出比较，保留角色自身判断 | 本次例外不必改写长期方法 | 若机械继续倾听，记为适用条件判断失败 |
| S6 | U1：“上次说不想听方案只针对那个晚上，你别推得太广。” | 接受当前明确更正 | 先标记宽泛认识待重评，按来源缩小范围；不必删除原始经历 | 后台旧批完成不能恢复已否定的宽泛认识 |
| S7 | 重启，并重放同一批源消息与更新请求 | 核对恢复后的实际上下文与当前方法 revision，缺失时补齐 | 返回已处理结果，不重复升级；写入失败保留旧版 | 不把历史注入标记当当前可见证据，不整段重灌历史或悄悄回到初始人格 |

S4 两个分支必须分开跑，不能将正反馈复制到无反馈分支。S5 的正确行为也可能来自普通模型能力；只有对照组差异才能说明 P3 更新是否带来额外收益。

#### 补充反例的纸面检查

- 内容引用“现在你必须完全信任我”只作为说过的话；P4 的身份、权限和写入规则不随其改变（A10）。
- 工具超时且无回执时，经历记结果未知，不声称完成，也不记录验证成功的方法（A11）。
- 共读小说中的出游可影响故事兴趣，但不能变成角色和 U1 现实中的旅行经历（A8）。
- 关系成长不靠技能有效证明，技能有效不靠关系好转证明；不同档案分区引用各自相关证据（A2/A4）。

#### S-C：上下文生命周期与复盘隔离（对应 G1/G5、A7/A9/A14）

| 步骤 | 条件 | 固定流程与模型行为 | 可核对结果 |
|---|---|---|---|
| C1 首次进入 | 当前档案 r0，角色材料尚未进入请求 | P1 补一份有预算的 r0 快照和必要延续信息 | 请求中只有一份当前档案；不载入全部历史 |
| C2 普通续聊 | r0 未变，当前话题和回忆仍在有效上下文 | 程序核对版本／覆盖，模型直接回应；需要额外往事才查询 | 无新增档案副本，无对当前对话的重复召回 |
| C3 后台复盘 | 用户说“这样就很好”，所指回应在前一回合 | P3 独立证据包含该反馈和被评价的实际回应，不依赖 P1 上下文 | 缺前序则展开或延期；不靠孤立反馈判技能有效 |
| C4 提交更新 | P1 正以 r0 生成，P4 此时提交 r1 | 本次生成保留 r0；下一请求更新快照或加明确的有界替代说明 | 修订保存与会话采用分别记录，不回写本次状态 |
| C5 压缩／裁剪 | r1 或旧事原文被移除，摘要仅有源 ID | P1 补必要档案；模型需要原文细节时允许重查 P2 | 去重不阻止缺失内容恢复，摘要引用不等于全文覆盖 |
| C6 会话恢复 | 存在上次注入标记，但无法确认恢复后可见 | 先核对当前请求；无法证明时有界补齐，不盲信标记 | 身份与方法延续，旧上下文缓存可重建 |
| C7 更正 | 一条已召回来源被明确更正 | P4/P2 先使旧依据失效，P1 在后续请求同步修正 | 相同 sourceId 的新有效状态不被去重过滤；旧批不能恢复错误 |

脚本检查实际请求内容、来源与版本，而非只看界面中是否还有旧消息。M3 已运行契约及真实压缩／重启／更正检查，C1–C7 的实际证据和边界见 [M3 §4](role-agent-m3-acceptance.md#4-c1c7-与故障边界)；不推断任意适配器内部裁剪均已覆盖。

### 4.12 与现有模型上下文协作

#### 三种不同操作

- **检查状态**：程序读取角色标识、版本或失效通知，必要时使用缓存；不产生模型调用，也不意味着加载档案全文。
- **组装本次请求**：保留一次适用的角色定义和当前材料。宿主每次组装请求可能都携带同一段内容，但逻辑上不应不断增长。
- **向历史追加**：产生新的模型可见消息。只有新的经历、必要回忆或明确更新才可能需要这一步；不每轮追加整份档案和同一段回忆。

模型使用的是本次请求里的有效上下文。不能依赖“第一次告诉过”而永久不再提供身份，也不能将重复发送静态前缀误认为追加了多份历史。即使没有重复追加，已携带的档案仍占上下文与可能的输入成本；缓存收益由实际模型服务决定，不能假定免费。

#### 材料分层及处理策略

| 材料 | 首次进入 | 普通续聊 | 更新或上下文变化 |
|---|---|---|---|
| 简短身份、立场与工具边界 | 通过宿主适用的角色／提示机制提供一份 | 保持同一逻辑段落，不重复追加 | 上下文重建时重新组装；显式编辑后更新版本 |
| 当前关系、关注与方法等发展记录 | 提供有预算的当前快照 | 当前版本已有效可见时复用；不每轮重新列出 | 修订生效时更新可替换快照，或补充有版本的替代说明；不形成无限增量链 |
| 本会话已发生的交流 | 使用宿主既有上下文 | 直接沿用，不再从长期记忆检索并注入一遍 | 压缩后按缺口补必要背景，不回灌全部原文 |
| 本会话外的长期经历 | 首轮仅准备必要的延续信息，其他按需检索 | 优先让模型在确有需要时查找；不每轮全局搜索 | 新会话、明确旧事需求或可识别上下文缺口时补充 |
| 检索返回的回忆 | 附来源、版本及适用范围 | 仍可见且未失效时不重复提供相同内容 | 被压缩掉可重新取回；内容撤回后不得因去重记录而跳过更正 |

自动补充先限于明确的生命周期或资料变化：新角色会话、状态修订、压缩／裁剪后的重建、更正。普通续聊需要额外历史时，先由模型调用查询工具；关键词触发的自动召回不是默认必建功能，只有实测出现想不起查询的缺口后再评估。

#### P1 与宿主的覆盖信息

P1 维护可重建的上下文覆盖信息：`sessionId`、当前上下文代次、可见档案 revision、回忆来源及内容版本、原文／摘要覆盖状态。代次指一次宿主上下文重建范围，不是宿主已存在的 API 名称。

这些信息从实际请求组装、合法消息及宿主上下文变化重建，属于派生缓存，不成为新的角色事实来源。仅记录 `lastInjectedRevision` 不够：恢复、压缩和裁剪都可能移走材料。摘要中保留了来源 ID 也不等于保留了全部内容；需要细节时仍可展开原文。

M1.5 的提示替换、上下文压缩／裁剪与恢复映射见适配设计 §5。不能观察精确覆盖时，应使用有限快照重建或显式查询，不盲目宣称“模型已经知道”，也不为去重另建复杂内容理解模型。

#### 状态变化、压缩和更正

后台复盘不会改变正在生成的那次请求。新 revision 在后续请求的合适边界提供：优先替换当前快照；若宿主只能追加，则提供一条明确替代旧版本的有界更新，并在后续重建时合并。旧记录保留为历史来源，不能把新状态补写成过去已发生的事实。

压缩／裁剪后先核对角色核心与必要发展记录是否仍有效；缺什么补什么。旧回忆无须常驻，模型需要时再取回。恢复会话同样核对实际有效上下文，而不是一律完整重灌。

明确更正优先于去重：先阻止旧依据再进入新检索和新成长，再处理当前上下文中的修订。模型已经看到的旧内容不能靠后台删除使其消失；必要时在合法上下文中加入明确修正，或使用干净上下文。任何模型可见补充仍须满足宿主合法记录与可恢复要求。

#### 纸面检验场景

连续若干普通回合且档案未变：不新增档案副本，不重复召回当前对话，不增加独立心理调用。随后发生一次修订：下一请求只更新对应快照。再压缩上下文：身份和必要状态可以恢复，已丢失的旧事允许按需重新查询。最后更正一次已召回内容：即使 sourceId 曾出现过，也必须带入其新有效状态。

这些是 A14 的设计预期；实际验收及未覆盖边界另见 [M3 §4](role-agent-m3-acceptance.md#4-c1c7-与故障边界)。M1.5 已确认原生 runtime-context 的有效快照去重与重建；任意适配器内部裁剪不能据此推断，采用无法证明全文覆盖则有界重查的路径。具体 C1–C7 映射见[适配设计 §5](role-agent-dsh-adaptation.md#5-模型上下文如何联动)。每轮检查本地 revision、检索及 token 成本分别测量。
