# 反馈识别与方法效果凭据修复

日期：2026-11-15。修复 [M3 验收](role-agent-m3-acceptance.md)发现的反馈误登记，落实 [M4 方案 §4.1](role-agent-m4-plan.md#41-反馈与复盘请求分开)。本次不实施其余 M4 检查／导出功能，不开始持续交流试用，不排查已暂缓的网络故障。

## 1. 问题与修改

旧链路是 `role_note_feedback({}) → 当前用户 sourceId 进入 feedbackSources → 可作为 supported 的反馈凭据`。工具同时允许请求复盘；没有效果方向、评价对象或方法关联，因此“想听建议”和更正也能污染升级依据。

新工具保留名字，要求显式 `kind`：

```json
{"kind":"review-request"}
```

只设置复盘优先级，不产生效果记录。效果评价则为：

```json
{
  "kind":"method-outcome",
  "polarity":"positive",
  "quote":"刚才先听再问的方式确实有帮助",
  "methodId":"实际快照中的方法ID"
}
```

`polarity` 必须为 positive／negative／unclear；`quote` 必须逐字存在于当前直接用户消息。`targetSourceId` 可显式指定当前角色内的旧回应；省略时指向本会话上一条已完成回复，避免让模型猜源 ID。跨会话目标另核对原生事件时间，同会话核对序号。未知目标、未来回应、未完成经历、错误工具结果、编造原话、未知方法均不能成为合格效果对象。

方法不明确时可省略 `methodId`，保留有对象的待评反馈，但不能支持方法升级。模型判断这段话是否真的在评价效果、实际回应是否采用了所指方法；程序校验来源、对象、类型、晋级与消费边界，不把结构校验当成语义真伪证明。没有增加每轮分类模型。

## 2. 升级与恢复约束

- 候选仍须先试用；只有新正向效果、对应同一方法、引用用户评价及实际试用目标，才允许 tried→supported。
- 已提交的实际试用保存在 `methodTrials`；新试用和后续评价也可在同一复盘批次核对，必须包含原始回应、同时引用评价和目标，再原子记录关联。只引用旧方法说明或别的方法反馈不能替代试用证据。
- 负面／不明确／未关联方法的效果，以及 review-request，均不能支持升级；同一次试用的后续负面评价会阻止选择性使用此前正向评价。
- 登记效果递增 evidenceRevision，旧的在途提案须重评；更正反馈来源或试用依据同时使关联效果失效并清理试用凭据。
- 完成批次时将涉及的效果标为 `consumedBy`；同一评价重放幂等，不重新提供晋级凭据。无更新也消费本批已评证据，未处理批次的评价保留。
- 后台证据包展开被评价回应的原始经历，即使该回应在另一会话或已经处理；展开不制造新经历，也不重新推进其采集。

持久结构是 v1 的附加字段 `outcomes`、`methodTrials`，旧记录通过 schema 默认空数组读取，不需要清空或另建角色。旧 `feedbackSources` 保留读取但不再授权晋级；旧 pending/proposed 提案仍按新规则校验，预算不会重置。历史已提交认识保留，不声称已自动重新认证全部旧 supported 结论。

## 3. 证据与验收

领域测试覆盖：真实试用＋正向评价可提交且只消费一次；负面、含糊、未关联和其他方法评价不可升级；旧标记不可晋级；假原话／未知或未来目标／非用户来源被拒绝；更正及并发登记使旧提案失效；旧结构重开；新试用与评价同批；同次试用后续负评价；跨会话时间与未完成目标。

真实 DSH 复验新增 `--scenario F`，10轮合成对话包含正向评价、请求建议、更正、负评价、含感谢的含糊评价、仅请求复盘及引用他人夸奖。另跑 `--scenario S --two-trials`，确认仍能从 candidate 经 tried 达到 supported。所有真实实验使用独立 home／bank，清理后保留合法会话、模型请求与报告，不重放日常聊天。

结果：程序回归253项、252通过、0失败、1项平台跳过。首轮 F 与正常晋级场景通过；重复 F 有一次正负评价漏登记，模型只口头回应，记录为失败 `LtJa7L`。随后强化“明确正负效果必须调用工具、不得只口头记下、未知方法先保存未关联评价”，最终同版本 F 连跑两次 `JaFylI`／`kuHV9o` 全部通过：正负评价均实际登记，五类非正向情境均未产生正向效果，复盘请求不生成效果记录。最终运行 bundle SHA 为 `9578e71224cd041d5261859f996726b8d09f62ad384f2772e0701f97784623bf`。

运行清单与逐轮分类、原文／目标／方法关联见 [修复运行清单](m3-evidence/feedback-fix-runs.json)和[脱敏结果](m3-evidence/feedback-fix-summary.json)。原始报告保留 `.tmp/m3/`，每次实现字节 SHA 随报告记录，重跑不覆盖失败历史。跨会话时间／原始序号检查和强制登记提示由最终版本回归及真实 F 场景覆盖；不把前一版本的正常晋级或重复运行改写为最终版本证据。上述结果是有限反例验证，不能保证所有自然表达永远无误判／遗漏。

完整回归结果见 `.tmp/m3/feedback-regression-final.log`。加载和产物仍按 `build --check`、L4、pack／verify-artifacts；最终固定包以 `dist/current.json` 对应的验证记录为准。反馈修复通过不代表长期成长收益已被证明，也不意味着 M4 全部建设完成。
