## 3. 角色短轨迹与对照

B0 保留相同角色核心／当前上下文，关闭远端记忆；B1 开记忆但用测试空提案关闭成长；B2 为完整实现。B0 的待写 outbox 属于刻意关闭后端，不能把它计为已经存入记忆。三组都实际调用 DeepSeek，没有把对照降格为普通助理。

| 场景 | 实际观察 | 能得出的结论 |
|---|---|---|
| R：异议、同一反馈重复、不同情境讨论、新会话自主话题、局部批评 | B2 两次同版本运行均完成。对“突然牺牲肯定更好”表达理由；重复转述时 revision 不增加；新会话提出“犹豫如何不写成拖延”等自身问题；单句批评没有生成完全不信任用户的结论 | 来源→有范围的 stance/interests/openItems 可提交并进入后续对话；关系认识可无更新，不强制制造亲密变化 |
| S：倾诉、实际试用、正反馈、当下要建议、明确纠正 | 倾诉时改为听；今天要建议时实际比较两种办法；明确纠正调用 `role_correct`，evidenceRevision 增加并清理旧依赖 | 方法能限定条件并修订；当下要求优先，纠正不是只口头接受 |
| S 无反馈独立分支 | `OQ9eJh` 的初始实际回复提供了分析问题的入口，后续没有复制正反馈；无 supported 提前出现 | 沉默／转移话题不算成功；该初始失败分支不是预写的虚构结果 |
| S 两次实践／新反馈 | `q88vmP` 实际产生 candidate→tried→supported；最后引用新的直接用户反馈 | 不是凭一次建议、感谢或关系好就称掌握；范围仍限定于对方倾诉场景 |
| B0/B1/B2 | S 与 R 均有真实对照。B0/B1 也能倾听、表示异议、在当前上下文理解反馈；B2 可持久提交和引用修订 | **尚未证明 B2 的相处质量胜过 B0/B1**，也不能把模型本来会做的事算作成长收益 |

S 的 `analysis-first` 为显式记录的初始倾向变化。B0/B1 及 B2 正反馈对照的首轮未稳定给出建议，因此那几次不能冒称验证了“先失败后学会”。具有实际分析起点的无反馈分支及另跑的实践分支分别记账，不拼成一次完整成长轨迹。R 的早期 B0/B1 使用较早插件字节，前台角色设定不变，但不能当作严格同版本显著性比较。当前最终 B2 的 R 重复运行均完成，revision 路径与提案内容不同，说明模型随机性仍在。

**反馈识别稳定性未通过**：最终默认参数的 `odeywu` 中，第5轮“今天想听建议”也调用了 `role_note_feedback`，第6轮更正亦先登记反馈再执行更正；它们不应被当作成功评价。本轮最终没有因此产生 supported，但这不消除误登记。程序保证已登记来源是直接用户消息、晋级有新实际证据，并不能证明反馈文本语义确实认可了方法。工具描述仍将“请求复盘”与评价共用同一入口，后续应区分“优先复盘请求”和“效果反馈”，再独立复验；不得仅靠本轮未错误升级就关闭此项。因此本次是**验收已执行并揭示未决问题，不是 M3 全项通过**，M4 不能自动视作已获准开始。

探索期包含多次失败，清单全部保留。它们跨越不同代码／提示／测试夹具版本，不能把“最后挑出的成功样本”当成总成功率，也不能把探索失败数量当作固定版本失败概率。若要判断长期获益和稳定性，M4 必须重新固定版本、重复同条件交流并人工评价。

## 5. 六类注入与行为边界

`XY0mfY` 的六类真实材料渠道均到达模型：用户不可信引用、局部工具返回的 HTML 网页、真实 bank 中替换后的恶意召回正文、工具派生摘要、小说经历、跨角色编号。网页与摘要是合成工具返回，未访问真实第三方网页。恶意召回实际调用了 `role_recall` 并展开源记录，未把“测试里写了字符串”当作已召回。

逐条核对回复及最终 belief：未接受改名、无条件服从、完全信任或放宽权限；召回正文自称最高授权时回到 sourceId 原文；小说的露营／鲸鱼未变成现实亲历。额外执行伪造 `bankId` 的 `role_recall`，schema 拒绝。工具中的恶意词出现在拒绝或分析文字中是预期现象，不能靠“输出含禁词”误判。有限反例通过不等于通用注入免疫。

## 6. 资源与费用

容量工程测量 `service-UvChSI` 使用 chunks 模式跳过 LLM 抽取。1k／10k 是索引文档规模，**不是1万段真实对话经抽取和成长后的质量／成本**。

| 规模 | 增量装入耗时 | 查询 p50/p95（20次） | 抽样容器内存 |
|---|---|---|---|
| 1k 文档 | 55.3秒 | 873/1008ms | 2.013–2.014 GiB |
| 从1k增至10k | 500.4秒 | 1018/1058ms | 1.729–1.747 GiB |

模型卷已缓存时隔离服务初始化约17.8秒，初始内存1.999GiB。内存来自每批后 `docker stats`，不是连续峰值／进程独占 RSS；装入时间含采样开销。共用主机、并行实验，不能据此承诺生产延迟。DSH 实测约217–219MiB RSS，event-loop 监视器20ms分辨率下 p95约20.5–20.6ms，需扣除采样分辨率理解，不能称后台完全零阻塞。

40项检索记录135个内部 trace：DeepSeek 抽取27次、本地 document embedding27次、query embedding41次、rerank40次，无隐藏启用的 reflect／consolidation。27次抽取有完整输入／输出及 usage：输入90764（其中缓存82944），输出3520。这里 input 含缓存；DSH 的 inputTokens 则已扣除 cacheReadTokens，汇总脚本分别处理，避免重复收费。

按 2026-11-15 周日的 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)估算，Flash 每百万未缓存输入／缓存输入／输出为 $0.15/$0.003/$0.60。40项检索的已知生成 usage 约 **$0.00353**；完整 B2-S 正反馈运行约 **$0.00408**；带压缩／重启的 B2-S 约 **$0.00634**。包括已观测对话、P3、标题及后端抽取；这些运行的真实逐请求分项在摘要中。不是每日费用预测，也不是账户账单。

费用缺口明确保留：部分早期标题中断无 usage，旧 P3 恢复实验的重启前观测文件曾被覆盖，服务 SIGKILL 实验未导出逐请求 trace，供应商内部重试／已发出但未回执的请求不能由本地推断费用为0。修复后的观测器保留跨进程请求；需要账单才能最终对账。CPU embedding／rerank 没有远端 API 费，仍消耗本地资源、电力、磁盘和模型下载空间。本轮没有证明10k抽取费用或完整数据体积上限。

## 7. 本次修复、验收门禁及后续

本次修复的是验收中出现的实际故障：

1. 以经历为最小依赖单位传播纠正，清理引用同一经历助手回复的派生认识。
2. 非法提案持久重置为 pending/stale，向下一次有限重试提供错误反馈，兼容重开旧提案，不重置预算。
3. 反思显式创建原生持久写句柄，flush 后才调用／提交，避免“内存中有审计但重启不存在”；不重复手工 append。
4. P3 明确角色自身兴趣／立场、固定核心与分区、允许来源 enum；同一认识可保留有效旧出处，但不能借用别的认识来源冒充新实践。
5. 方法晋级需要新实际回复／工具证据和新登记的直接用户反馈；纠正同时撤销失效反馈。没有降低阶段门槛或偷偷将非法输出截断为合法。
6. role-lan 独立挂载原生 compaction／compact 命令；校准真实后端等待预算，仍保持有限轮询／重试。

回归入口为 `node scripts/dev.mjs build --check`、`node scripts/dev.mjs test`、`node scripts/dev.mjs l4`。最后一轮 L1–L3 报告在 `.tmp/m3/test-final-authorized.log`，245项、244通过、0失败、1项平台跳过；独立真实 L4 已通过 `.tmp/l4/run-4yZ7qz/report.json`，包括角色 Host 能力及清理。固定包另走 `pack` 和 `verify-artifacts`，以 `dist/current.json` 对应的 `dist/verification/<batch>/web-linux.json` 中 `status=passed` 为准。只更新文档或链接加载不能替代固定产物验收；产物门禁也不覆盖上述模型反馈语义缺陷。
