# DSH 虚拟伙伴插件调研

> 当前方向见[角色成长设计方向与研究依据](role-agent-research.md)。本文保留插件参考，不以既有插件能力限定目标或定义成长机制。

调研日期：2026-11-10。目标是为长期相处、跨平台保持身份连续的虚拟伙伴寻找可参考的模块设计。

学术与大厂研究补充见 [虚拟伙伴 Agent 的人格记忆与主动交互研究](virtual-companion-agent-research.md)，覆盖截至 2026-11-11 的相关架构、评估与用户研究。

人格与记忆是核心：人格决定角色是谁、怎样回应，记忆保存共同经历和对用户的理解。主动性决定何时跟进或分享；平台插件提供观察、收消息和执行动作的接口。跨平台连续性还需要身份关联、会话管理和记忆使用范围，不能只靠各个平台复制同一段人设。

本文依据当日作者公开文档及本地 DSH `0.2.2-rc.1` 包文档整理，未安装运行这些社区插件，也未完成源码审计或组合兼容性验证。下文“模块”是功能归纳，不代表上游已经将其拆成独立可复用的包。链接指向持续变化的上游，未固定提交。

## 六个接入项目的模块对比

| 项目 | 平台用途 | 平台操作之外的重点 | 适合参考的方向 |
|---|---|---|---|
| `dsh-bili-pond` | B 站内容筛选与评论互动 | 偏好、跨天记忆、角色日记、排班、回应条件、执行账本 | 自主活动与经历沉淀 |
| `dsh-bili-workbench` | B 站互动及内容制作工作台 | 固定人格、用户画像、工作经验、经历流、复盘、长期任务 | 人格与分层记忆 |
| `@seiuna/dsh-bilibili-plugin` | B 站工具与通知接入 | 会话归组、上下文补全、缺失标记、凭据管理 | 外部话题如何变成连续会话 |
| `LockyBee/dsh-douyin-agent` | 抖音浏览与好友互动 | 共同人格、兴趣学习、自主活动、记忆共享范围、预算及收据 | 从真实行为形成兴趣 |
| `@xmanrui/dsh-im` | 多渠道私聊与群聊接入 | 机器人配置、身份映射、会话绑定、输入管理 | 同一伙伴的多个交互入口 |
| `dsh-im-humanize` | IM 拟人化交互 fork | 分段、阅读延迟、活跃程度适配、回合打断、主动回复投递 | 对话节奏与过期回复处理 |

### dsh-bili-pond

读取 `AGENTS.md` 中的关注方向、排除项和筛选标准。每轮留下少量可跨天使用的偏好和观察，另外用角色口吻写每日经历与感受。调度控制时段、轮次、间隔及额度，同一时间只运行一轮。

回应策略区分可触发回复的人与场景，并跳过低价值内容。账本区分看过、挑中和真正发送成功，防止重复处理或把尝试当成完成。

可借鉴的是把经历、提炼记忆和日记分开；日记可以有角色表达，但事实仍应回到原始事件。后一句是本文的设计建议。来源：[项目 README](https://github.com/YOYOLnFu/dsh-bili-pond)。

### dsh-bili-workbench

人设在设置中维护，每次生成时注入，不由任务复盘改写。记忆分为用户画像 `USER.md`、工作经验 `MEMORY.md` 和经历流 `events.jsonl`。它支持任务后复盘、按题材召回经历，以及查看、删除记忆。

其他模块包括主人与普通用户的身份区分、长期任务进度与重启恢复。工作经验主要服务内容生产，不能直接等同于情感关系记忆。

适合借鉴“稳定人格与可修正的用户理解分开存放”。来源：[项目 README](https://github.com/Userluckytian/dsh-bili-workbench)。

### seiuna B 站插件

同一视频或动态下的评论归入同一 DSH 会话，不同用户与楼层可以延续话题；不同内容、工作区和模型配置仍分开。收到通知时补充标题或正文、根评论及机器人回复，查不到的信息标记缺失。

此外提供凭据管理和操作预览。文档没有明确描述独立的人格成长或长期记忆模块；会话历史不等于跨会话长期记忆。

适合借鉴“输入一句话之前，先恢复它所在的话题”。来源：[项目 README](https://github.com/seiuna/dsh-bilibili-plugin)。

### LockyBee 抖音助手

插件与独立软件共用人格卡，兴趣另按实际播放进度、观看比例和确认互动更新，不把接触过的主题直接当成喜欢。自主活动在时段与额度内决定继续、换片、停止或分享。

聊天使用共同人格与允许共享的记忆，可配置 QQ 共享记忆。观察层区分已读内容、只识别到卡片及未观察附件；执行层保存用量和发送收据。

适合借鉴“稳定人格、变化兴趣、真实观察证据”三者分离。当前文档要求 Windows 与 Edge；真实公开评论发布确认仍待验，不能视为当前 Linux 环境的即用方案。来源：[项目 README](https://github.com/LockyBee/dsh-douyin-agent)及[插件说明](https://github.com/LockyBee/dsh-douyin-agent/blob/main/docs/plugin.md)。

### dsh-im

各机器人分别配置工作区、模型及会话绑定。它管理新建、切换与解绑会话，提供上下文增强，并记录渠道、聊天、线程和发言人身份。其他插件可通过查询接口与绑定事件获知会话来源和变化。输入侧支持批量消息及运行中补充指令。

适合借鉴身份与会话路由。渠道映射不等于已经关联同一个人在不同平台的账号，也不等于所有会话共享记忆。来源：[项目 README](https://github.com/xmanrui/dsh-im)。

### dsh-im-humanize

这是 `dsh-im` 的 fork，不应当作必须叠装在上游之上的附加模块。它增加模型主动分段、阅读延迟、段间停顿、活跃聊天加速，以及输入状态和表情反馈。新消息到来时可选择打断、排队或纠偏；被替代的旧回合静默取消，减少双回复。

它也能把主动唤醒或后台任务完成后的回复投递回绑定私聊，但投递本身不决定何时主动发起活动。它主要改变对话表现，不自动提供独立人格与长期记忆。来源：[项目 README](https://github.com/john-walks-slow/dsh-im-humanize)。

## 虚拟伙伴的建议模块划分

以下是设计参考，尚未成为本仓库的实施方案或 ADR。

| 模块 | 负责什么 | 不应混淆的边界 |
|---|---|---|
| 人格 | 身份、价值倾向、表达习惯 | 核心人格不应被每次摘要自动重写 |
| 用户与关系 | 账号关联、称呼、关系历史、信息可见范围 | 同名用户不自动视为同一个人 |
| 经历与记忆 | 来源、事实、提炼、召回、修正与删除 | 推测、角色感受和真实事件分别保存 |
| 兴趣 | 根据实际经历逐步形成偏好 | 接触过不等于喜欢，也不等于用户喜欢 |
| 主动活动 | 探索、跟进、分享与休息的时机 | 调度到期不代表必须打扰用户 |
| 会话管理 | 话题连续性、群聊和线程、会话切换 | 会话历史不代替长期记忆 |
| 对话节奏 | 分段、等待、打断和过期回复取消 | 模拟延迟不代表有独立人格 |
| 执行记录 | 尝试、结果、收据、去重和恢复 | 模型声称做过不等于实际完成 |
| 平台适配 | 内容观察、消息收发、平台操作 | 平台适配不应各自维护互不关联的角色身份 |

建议先建立人格、分层记忆、身份与关系范围，再增加兴趣和主动活动。平台之间共享角色身份，但根据场景调整表达：私聊可以亲近，公开评论需要适合陌生读者；私聊记忆可用于理解用户，不应直接公开引用。

对于本仓库实现，还需遵守会话日志为模型可见事实来源的约定。外部插件的 JSONL、Markdown 记忆或执行账本设计只能作为参考，不能绕开已提交 session event，也不能直接照搬未知 session event 类型。内存状态应可重建。

## 后续验证问题

1. 人格注入到哪些调用：普通聊天、后台任务、摘要模型和平台自动回复是否使用同一份配置？
2. 记忆归属是谁：按 profile、角色、用户、会话还是平台隔离？跨平台账号如何显式关联？
3. 召回是否保留来源、时间与使用范围？用户纠正、撤回或删除后怎样生效？
4. 平台插件是否自行调用模型，绕过 DSH 人设及记忆扩展点？
5. 主动活动与投递是否分离，能否取消、限额、暂停并防止重复发送？
6. 多个记忆插件是否重复注入、相互覆盖或重复总结？初次试验宜只选一个记忆后端。

一个最小体验验证是：用户说“累的时候先听我吐槽，别急着给建议”，换会话后仍能适当回应；随后说“今天想听建议”时，当前表达优先；在公开平台回复时，不泄露这段私人对话。跨平台测试还应核对真实身份关联和同一人格是否生效。
