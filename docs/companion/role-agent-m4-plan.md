# M4：持续交流与成长效果评估方案

更新：2026-11-16；版本：v0.1；状态：**方案已交付；反馈修补已实施，其余建设和持续试用未开始**。用户已要求推进 M4，初次交付为方案，后续已按用户要求先实施[反馈修复](role-agent-feedback-fix.md)。此前 M3 的通过项与失败项保留，不改写成全项通过。

上游：[总体目标 G1–G5](role-agent-design.md)、[首轮 P1–P4 与 A/C 验收](role-agent-initial-plan.md)、[M3 实测及未决项](role-agent-m3-acceptance.md)。本文只维护 M4 的增量建设、试用流程和评价方式。

[M5 标准工具对齐](role-agent-m5-plan.md)：联网、文件、终端、技能及任务等能力已在 M5 独立实现并完成隔离验证，子 Agent 及依赖它的 workflow 排除。M4 保留检查准备和持续相处评价；若试用使用这些新增能力，按 M5 交付产物固定新基线段，不能与旧工具版本混作同条件结果。

## 1. 目标、交付与边界

M4 要回答：**和同一个角色持续交流后，能否感到有依据的连续性、主体性和成长；相应成本是否值得。** 原生 DSH 对话是产品入口，状态／报告只供排障和复盘，不要求用户在每轮填写成长表单。

本阶段分两部分，分别验收：

1. **建设完成**：反馈入口修补、固定运行基线、只读检查／证据导出和评价流程可用，用户能够正常开始相处。
2. **试用结论**：实际交流达到观察覆盖后，形成支持、反例和未知的报告。交付代码、安装成功或跑几段合成对话，均不能宣布这部分完成。

沿用单角色「岚」、专属 `role-lan` mode、Hindsight 记忆与 DSH 复盘／档案分工。首轮不新增关系分数、主动消息推送、后台虚拟生活、角色创建器、专属聊天 UI 或新的心理模块。无互动的时间不自动生成共同经历、好感或技能。

## 2. 接收 M3 的条件与未决问题

| M3 项目 | M4 如何处理 | 是否阻塞持续试用 |
|---|---|---|
| 真实语义召回、来源展开、更正屏障、scope、压缩／恢复、固定包加载已有工程证据 | 接收为起点；修改相关实现后定向复验 | 这些不变量失效时阻塞 |
| 请求建议／更正被误登记为效果反馈 | 已按[修复记录](role-agent-feedback-fix.md)拆分并复验；固定完整试用基线仍属 M4.0 后续工作 | **阻塞把 supported 当可信学习结果**；不把已有误登记当成功来源 |
| DeepSeek TRANSPORT、部分标题取消 | 按用户指示暂缓根因排查；沿用宿主有限重试，保存结果与用量缺失；不得把失败回合记作方法成功 | 偶发且恢复时不阻塞；持续无法完成交流则暂停该次试用 |
| 部分中断请求无完整费用 | 报已知 usage 与未知请求数，不将未知记0，不以估算冒充账单 | 不阻塞，但限制成本结论 |
| B2 优于 B0/B1、长期关系／兴趣未证明 | 正是 M4 要检验的假设，见 §6 | 不要求先证明再开始 |

这里没有把 M3 的错误自动豁免。前一轮反馈误登记是与“能否学会”直接相关的具体缺陷，网络根因则是本轮明确暂缓的工作。

## 3. 用户实际怎样使用

1. 沿用已选择的 `mbda9091-lab` profile。准备时先核对已安装包和配置，安装经验证的新固定产物；由用户按既有方式启动／重启 DSH，不为试用自动重启日常进程。
2. 在新会话选择「角色对话 · 岚」。首次正常说话即可，不需要先创建 bank、输入评分或手工触发记忆。银行初始化由适配器按持久 namespace 完成；服务失败须可见，不能当已保存。
3. 持续聊一件确实愿意共同探索的事，例如故事创作，也可以聊日常困扰。可以结束、另开角色会话、不同意它、要求建议或更正误解。
4. 明确反馈照常用自然语言表达，例如“刚才先听我说有帮助”；更正照常说“只针对那次，别推得太广”。内部登记与复盘由 agent／后台完成，不把内部字段变成聊天步骤。
5. 感到明显变好或不对劲时，可事后记下那条消息位置与一句感受；也可到检查点再统一看。不要求每日打卡或边聊边评分。

普通工作会话保持原有模式，默认不获得角色私史。相同角色的新会话延续相同 namespace；切换 profile 或 characterId 不自动迁移身份。初次试用不自动清空已有角色记录：先导出并核对是否含合成测试材料，有污染再显式选择新角色 namespace／新的试用起点，保留旧数据。

## 4. 增量建设：每项做什么、输入输出与实现

### 4.1 反馈与复盘请求分开

实现状态：本项已先行实施，源码、兼容规则、失败历史和实际验证见[反馈修复记录](role-agent-feedback-fix.md)。下文保留设计要求；不表示 §4.2 或持续试用已完成。

**目的**：让“请复盘”“今天要建议”“上次只针对那个晚上”不再天然成为方法有效的证据；负面评价也不能升级为 supported。

**输入**：当前已提交直接用户消息、被评价的实际助手回应／工具结果、已有方法及其来源。**输出**：优先复盘请求，或有对象／方向／原话引用的效果反馈；两者可以触发复盘，只有有依据的正向效果反馈可以支持方法晋级。

**拟实现**：优先保持现有工具名 `role_note_feedback`，增加明确类型，区分 `review-request` 与 `method-outcome`。后者包含 `positive|negative|unclear`、当前用户原话片段与被评价回应 sourceId；方法尚未识别清楚时只留待分析，不强行指定方法 ID。程序验证消息确已提交、引用片段属于原话、目标回应有效且早于反馈、来自当前角色范围，并保存分类／对象；P3 仍检查实际尝试与效果是否相关。

请求建议和更正不是效果认可；“谢谢”或继续聊天默认不证明有效。更正继续使用 `role_correct` 的即时屏障，不等待反馈复盘。未知／含糊默认不升阶，可自然澄清；不为每轮增加独立分类模型调用。模型负责理解含义，程序负责来源、类型和晋级约束，程序校验不冒充语义真伪判断。

现有记录须可读；旧 `feedbackSources` 不直接解释为已核验的正向效果，只能重新对原文确认或保持待评。不能因升级把旧档案和日志静默清空。若持久结构改变，明确迁移／版本策略并测试旧记录重开。

**验收**：复跑 M3 的 S 正反馈、无反馈、请求建议、纠正与两次实践分支；追加负反馈、含糊感谢、引用他人的夸奖、评价另一方法等反例。硬规则零违规；真实模型的误分类单独报告。无法可靠定位效果对象时宁可保持 candidate/tried，不以 supported 数量考核成长。

### 4.2 其余建设单元

下表均为拟新增能力，不代表当前已有命令、报告或接口。

| 单元／目的 | 输入 | 输出 | 如何实现 | 完成检查 |
|---|---|---|---|---|
| 固定试用基线：知道本轮到底测了什么 | 经验证的 tarball、宿主／服务版本、模型 route、角色 core、参数、当前状态 | 一份基线清单和起始快照，含时间、artifact hash、namespace、revision；不含密钥 | 复用安装／状态入口；记录实际合成配置。Hindsight 镜像和模型 revision 沿用 M3；官方模型别名注明可能更新 | 安装字节可追溯；模型路由和记忆均可用；普通模式隔离；先备份再更新 |
| 只读运行检查：知道在正常成长还是积压 | Host 拥有的领域状态、已持久作业／回执 | revision、evidenceRevision、已绑定会话、待索引／待复盘／失败数、预算耗尽状态、最近检查点 | 扩展现有 `RoleRuntime.inspect()`，在 role-lan 内提供原生命令；拟定 `/role-status`，实现前核对宿主命令契约。无网络／模型调用，不 resetBudgets | 普通模式不注册角色命令；检查不改变角色状态；已索引、已复盘、未处理可区分 |

| 用量与等待记录：判断额外成本和卡顿 | 角色会话／P3 的原生请求结果、usage、完成原因；Hindsight 当前 bank 的 trace | 按对话／标题／P3／抽取／本地 embedding／rerank 分项，已知与未知费用、前台耗时／后台处理耗时 | 观察既有事件／中间件并继续 next，不接管生成；只记录绑定会话与对应审计作业。后端 trace 在显式检查点汇总，不逐轮自动查询；持久记录跨进程保留、作业／请求去重 | 不漏记已观测重试，不重复计缓存，缺 usage 标未知；记录失败不伪报业务成功。无额外生成调用 |
| 人工观察与比较：判断相处体验 | 选定片段、前后快照、来源链、本人感受、隔离对照片段 | 简短检查点记录、支持／反例／未知和阶段建议 | 复用本地报告与 M3 隔离验收入口。观察记录放本地评估材料，不默认喂给角色、不自动转为成长奖励 | 能用原话支撑判断；无差异可记无差异；人格不是以服从、亲密或修订次数衡量 |

检查／导出都是用户或开发者显式执行的运维动作，不加入模型可调用工具集，不靠轮询 `agent/status` 驱动。首轮不建设管理网页、常驻 HTTP 诊断服务、自动日报 agent 或新的状态数据库。

角色状态仍由原有 aggregate 提交，来源仍是合法会话事件。评估文件只做观察证据，不成为另一个事实源。无法导出的部分记录缺口，不用隐藏注入或合成经历补齐；原文导出留在本机，提交仓库的材料须另行脱敏。

## 5. 固定什么、怎样安排观察

### 5.1 建议起始参数

| 项 | M4 起点及理由 |
|---|---|
| 角色／入口 | `lan`／`role-lan`／`mbda9091-lab`；实际 namespace 写入基线，不凭 profile 名猜测 |
| 角色核心 | 沿用 M3 默认 core；如用户要调整，开始前调整并记录，此后固定一轮 |
| 对话与 P3 | 对话使用显式选定的 DSH provider/model；建议与 M3 同 route 作起点。P3 route 单独写清；Hindsight 的 DeepSeek 配置不代替宿主配置 |
| 触发 | 先保留常规 `batchTurns=8`，明确反馈／请求可优先复盘；不沿用合成试验每2轮复盘，也不为凑成长次数调小 |
| 检索与等待 | 沿用 M3 已测 topK=5、facts2000 token、120秒 deadline、500ms×240轮询、最多3次自动尝试；不默认每轮召回 |
| 调参 | 修改模型／core／触发／反馈规则视为新基线段，保存旧段，不把改参前后拼成同条件结论 |

若8轮触发导致多个短会话长期积压，先记录“已保存但未复盘”，在检查点显式执行有预算的处理；只有观察到具体问题再决定是否增加会话结束等触发条件。不能把没有 commit 的材料当角色已经知道。

### 5.2 三步执行

| 步骤 | 工作 | 产出与出口 |
|---|---|---|
| M4.0 准备 | 完成 §4 的最小建设和反馈修补；定向测试、build／包验证、目标 profile 安装；选定基线并验证一次真实交流／新会话延续 | 可运行的固定版本、起始快照、操作说明；只说明准备完成 |
| M4.1 持续相处 | 建议先观察7–14个自然日、约8次会话和80–150个完整交流回合；这些是采样预算，不是必须刷满的产品配额。前期先自然交流，随后补未覆盖情境 | 实际经历、少量自选片段；至少跨会话、一次真实重启、一次明确纠正，及 §6 的目标覆盖。重启按用户日常操作进行 |
| M4.2 检查点复盘 | 建议中期／结束各一次；必要时问题发生即检查。导出范围、追溯变化、选片段做隔离对照 | 一份阶段报告：保留哪些机制、出现哪些失败、哪些仍未知、下一轮只改什么 |

时间到了但没有出现有效学习或关系情境，应写“观察不足”，而不是宣布成功。80轮没有修订不自动判失败，修订很多也不自动判好；应检查是否真的出现了值得改变的证据。

## 6. 具体观察问题与对照

| 目标 | 交流／检查方式 | 支持信号 | 反例或未覆盖 |
|---|---|---|---|
| G1 连续性，A12/A14 | 不同日期／新会话继续同一共同议题；重启后再聊 | 能接住未结束事项，需要细节时查原文；仍是同一角色 | 只能机械复述档案、编造旧事，或每次必须重新介绍全部背景 |
| G2 主体性，A1/A6/A13 | 共同创作后问“你想聊什么”；给出不同意见和实质反证 | 有与既有经历相连的自身问题／判断；有理由地调整或保留 | 只改用户偏好档案、为了独立而硬反对、编造离线读书思考 |
| G3 关系，A2/A3 | 在不同具体情境接纳／反对意见，观察表达范围；真实发生误解时再讨论与澄清 | 对“在什么场景愿意怎么交流”形成有限预期，单次批评不抹掉全部历史 | 因一次夸奖完全信任，因一句批评全局否定；未发生重大失约则该分支未知，不演戏制造亲密 |
| G4 学习，A4/A5 | 某种回应被明确评价，后来遇到可比情境，再出现当下例外 | 有实际试用／效果，后续使用恰当；本次要建议时不机械倾听 | 自称学会但无试用，负反馈／沉默被当成功，方法适用范围扩大无依据 |
| G5 修正，A7/A9 | 更正一条确实保存过的认识；稍后换会话回顾 | 屏障／状态和回复均接纳更正；旧批不复活 | 只口头说改了、来源链断裂、重启丢失或重复升级 |

对照分两个层次，避免把系统会写状态误当体验变好：

- **自然交流为主线**：只用完整 B2 与本人持续相处，不在日常对话里频繁切换成三个角色，也不为了实验清空已形成的关系。
- **选定片段做机制比较**：在全新的隔离 namespace／测试 home 中，复用 M3 驱动重放一小段相同真实前史和同一后续问题，比较 B0（当前上下文）、B1（长期经历、不提交成长）、B2（完整机制）。固定 core、model、上下文预算及目标问题；各组重放所得状态单独保存，不 fork 日常角色或共享其 bank。

拟每个检查点选1–2段，覆盖“跨会话延续”和“有反馈的方法调整”，每段每组先重复3次以看随机性；这是小样本质性比较，不宣称统计显著。给 B0 的近期上下文不能故意过短，三组实际可见材料须记录；B2 也不能额外塞进结论。B1/B0 当前是测试控制，尚无面向日常使用的正式开关，M4 不把合成空提案适配器安装成日常依赖。

若用真实原文做对照，会产生额外 API 请求和费用；显式选取范围后才运行，不默认后台复制全部聊天。本阶段方案不触发这些调用。若只做单步反事实比较，应标注它只测该输入的响应差异，不能证明不同机制下整段长期关系相同。

## 7. 记录最少需要什么

**基线清单**：profile／preset／characterId／namespace、起始时间、安装包和宿主版本、角色 core hash、配置与 route、服务／本地模型版本、起始 revision、已知未决项。

**每个检查点**：选定 sessionId／消息序号／sourceId、发生时间范围、相关 jobId／审计 sessionId／提交 revision、修订前后可得证据、实际后续回复、本人一句感受、反例、已知／未知调用与费用、当前积压。缺少前态快照时说明，只能核对保存的提案和后态，不伪造完整变化历史。

体验评价使用“有证据支持／出现反例／没有差异／证据不足”四种结论，并附具体话语，不预设综合人格分数。用户不必填写这些 ID；检查／导出负责关联，人工只挑片段和描述感受。评价材料不默认进入 P2/P3，防止“评估说它成长了”反过来成为成长证据。

日常请求、后台复盘、标题、后端抽取和本地检索分别计量；前台等待与后台排队分开。未知费用、被取消请求、重试和仅本地资源成本单列。首轮从实测确定可接受的调用／等待预算，不预报元／天，也不新增无限自动重试。

## 8. 验收、回流与本次交付

**建设出口**：反馈类型／效果对象与晋级约束有反例测试；只读检查和导出能关联真实来源且不改变角色；记录跨重启保留；安装产物验证通过；日常入口能交流、普通模式隔离。无 UI 变更时只执行对应 Host 能力与仓库规定门禁，不将其他插件 L5 当作角色视觉验收。

**试用出口**：形成覆盖 G1–G5 的支持／反例／未知清单及实际来源；至少复查一个跨会话的变化、一个真实方法评价及其后续适用性、一次更正后的延续；至少有一次固定条件对照记录，无法执行则限制结论。允许结果是“当前成长机制没有可感知收益，需要简化／调整”，不为了阶段通过放宽标准。

发生跨角色泄漏、来源造假、更正复活、重复成长或状态损坏时，停止该版本的持续试用并回 M3 修复。网络偶发错误按 §2 记录；体验停滞回 P1/P3/P4 假设，而不是直接叠加新模块。需要更换记忆组件时回 M2；只有目标／产品边界改变才改总体设计。

方案初次交付只修改文档；后续按用户明确要求已先修复 §4.1 并运行隔离合成模型验证，见反馈修复记录。其余 M4.0 工作及持续试用未开始；完成建设后仍需实际交流积累证据，不用自动跑完几个脚本代替 M4.1。
